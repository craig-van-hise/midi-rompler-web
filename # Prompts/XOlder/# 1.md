# Product Requirements Prompt (PRP) — 🔵 Active

## 1. Project Context & Objectives
The "Electric Piano" instrument patch in the MIDI Rompler is currently defective. The `AudioEngine` attempts to map it to an `electric-piano` folder on the `nbrosowsky` GitHub Pages CDN, which does not exist, and relies on an incorrect fallback to the acoustic `piano` folder with an incompatible file mapping. 

The objective is to fix the Electric Piano by decoupling it from the default CDN and pointing it directly to a known, stable Web Audio asset source (`tonejs.github.io/audio/casio/`) while maintaining the existing architecture for the other three instruments.

## 2. Technical Decisions & Dependencies
* **External Asset Source:** We will NOT host audio samples locally. To resolve the missing `electric-piano` patch, we will utilize the official Tone.js sample repository.
* **Target CDN URL:** `https://tonejs.github.io/audio/casio/`
* **Sample Map Constraint:** The Casio patch relies heavily on pitch interpolation by the `Tone.Sampler`. You must limit the `electric-piano` sample map to exactly `'A1': 'A1.mp3'` and `'A2': 'A2.mp3'`. Tone.js will handle the repitching for the rest of the keyboard.
* **TDD Environment:** The agent must write tests to verify the routing logic. If a test runner (e.g., Vitest) is not installed, the agent must install it (`npm i -D vitest`) to execute the checkpoints.
