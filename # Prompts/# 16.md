# Product Requirements Prompt (PRP) — ✅ Completed

## 1. Project Context & Objectives
The application currently suffers from a critical crash (`Uncaught Error: No available buffers`) if a user triggers a MIDI note while an instrument is actively downloading its samples. Additionally, the silent auto-start mechanism fails to inform the user that Web MIDI input cannot unlock the browser's AudioContext, leaving the user confused when no sound plays.

The objective is to:
1. Implement a strict `isInstrumentLoading` lock inside the `AudioEngine` to silently ignore MIDI/UI notes until the buffer is 100% ready.
2. Implement a UI warning system that detects if a user attempts to play MIDI while the `Tone.context` is suspended, explicitly instructing them to click the page.

## 2. Technical Decisions & Dependencies
* **Engine Locks:** Wrap the `loadInstrument` logic in a `try/finally` block that toggles an `isInstrumentLoading` boolean. The `noteOn` and `releaseNote` methods must abort early if this lock is true.
* **AudioContext State Checking:** In the MIDI message handler, check `Tone.context.state`. If it equals `'suspended'`, the system must trigger a visible React state warning instructing the user to interact with the DOM.
* **Trap Resolution:** The existing `pointerdown`/`keydown` trap must not only initialize Tone.js but also clear the UI warning state.

## 3. Implementation Phases

* **Objective:** Prevent the `AudioEngine` from attempting to play incomplete buffers.
