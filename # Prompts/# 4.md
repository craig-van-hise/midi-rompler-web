# Product Requirements Prompt (PRP) — 🔵 Active

## 1. Project Context & Objectives
The user requires a high-quality, multi-sampled Electric Piano without manually downloading and hosting the audio files. The objective is to integrate the `smplr` library, which provides a dedicated CDN and Web Audio mapping for classic electric pianos (like the Wurlitzer EP200). The worker agent must install this library, instantiate it for the 'electric-piano' patch, and correctly route its output into the existing Tone.js effects chain (`this.panVol`).

## 2. Technical Decisions & Dependencies
* **New Dependency:** Install `smplr` (`npm install smplr`).
* **Instrument Architecture:** * Acoustic Piano, Acoustic Guitar, and Electric Bass will continue using the existing `Tone.Sampler` and `nbrosowsky` CDN.
  * Electric Piano will use `smplr`'s `Soundfont` or `ElectricPiano` class (e.g., the WurlitzerEP200), fetching automatically from the `smpldsnds` CDN.
* **Audio Routing:** `smplr` instruments output native Web Audio API nodes. Tone.js nodes (like `this.panVol`) wrap native nodes. The agent must configure the `smplr` instrument to output to `Tone.getContext().rawContext.destination` or explicitly route it to `this.panVol`'s underlying native audio context.
* **Typing Adjustments:** `this.sampler` in `AudioEngine` will need to be widened to support either a `Tone.Sampler` or the `smplr` instrument instance, with conditional logic applied in the ADSR and triggering methods (since `smplr` uses `.start({ note: ... })` instead of `.triggerAttackRelease()`).
